# Shipping the Gradespace mobile app

The app ships as three variants. Each one installs separately, so you can have all three on one phone.

| Variant     | Home-screen name   | Bundle id / package          | Scheme                  |
| ----------- | ------------------ | ---------------------------- | ----------------------- |
| production  | Gradespace         | `com.gradespace.ide`         | `gradespace://`         |
| preview     | Gradespace Preview | `com.gradespace.ide.preview` | `gradespace-preview://` |
| development | Gradespace Dev     | `com.gradespace.ide.dev`     | `gradespace-dev://`     |

The widget, share extension and app group ids come from the bundle id (`<bundle id>.widgets`, `<bundle id>.sharing`, `group.<bundle id>`). EAS registers them for you.

Run every command below from `apps/mobile`.

## 1. Install the EAS CLI and log in

```sh
npm install -g eas-cli
eas login
```

## 2. Create the EAS project

```sh
eas init
```

Choose your Expo account. EAS creates a project with the slug `gradespace-ide`.

`app.config.ts` is generated by code, so `eas init` can't save the project id into it. It prints the id instead (`eas project:info` shows it again). Keep the id for the next step.

## 3. Set the account values

These values aren't secret. The config reads them from the environment and leaves each one out when it isn't set:

| Variable                       | Value                                                                             |
| ------------------------------ | --------------------------------------------------------------------------------- |
| `T3CODE_MOBILE_EAS_PROJECT_ID` | Project id from `eas init`. It also turns on over-the-air updates.                |
| `T3CODE_MOBILE_EXPO_OWNER`     | Your Expo username or organization.                                               |
| `T3CODE_IOS_TEAM_ID`           | Your 10-character Apple Team ID, from developer.apple.com → Account → Membership. |

You need to set them in two places:

1. **On your Mac**, so the `eas` commands can read them. Add them to `.env.local` at the repo root, which git ignores:

   ```sh
   T3CODE_MOBILE_EAS_PROJECT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   T3CODE_MOBILE_EXPO_OWNER=your-expo-name
   T3CODE_IOS_TEAM_ID=ABCDE12345
   ```

2. **On EAS**, because build servers never receive `.env.local`. Add the same three variables as plain-text variables for the development, preview and production environments. Use expo.dev → your project → Environment variables, or run this for each variable:

   ```sh
   eas env:create --name T3CODE_MOBILE_EAS_PROJECT_ID --value <id> \
     --environment development --environment preview --environment production \
     --visibility plaintext
   ```

Check the result with `APP_VARIANT=production npx expo config --type public`.

Optional settings:

- `T3CODE_MOBILE_VERSION` sets the store version string. It defaults to `2.2.0`, so set it to `1.0.0` for a first release. The `testflight` build profile pins it to `3.0.0`, so use the `production` profile instead.
- Sign-in and T3 Connect need `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`, `EXPO_PUBLIC_CLERK_JWT_TEMPLATE`, `T3CODE_RELAY_URL` and `T3CODE_MOBILE_CLERK_RELYING_PARTY` (your Clerk frontend API domain). Leave all four unset unless you run your own Clerk instance and relay. See section 8.

## 4. Apple setup

1. Run your first iOS build (step 5) and let EAS manage credentials when it asks. It registers `com.gradespace.ide` and the extension ids, turns on the capabilities they need (App Groups, push), and creates certificates and profiles. You can also register the bundle id yourself under developer.apple.com → Identifiers.
2. In App Store Connect, go to Apps → **+** → New App:
   - Platform: iOS
   - Name: `Gradespace IDE` (store names must be unique; the home-screen name stays "Gradespace")
   - Bundle ID: `com.gradespace.ide`
   - SKU: any value
3. Open the app → App Information and copy the numeric **Apple ID**. That is the `ascAppId`.
4. Add it to `eas.json` under `submit.production`:

   ```json
   "production": {
     "ios": { "ascAppId": "1234567890" },
     "android": { "track": "internal" }
   }
   ```

   Without it, `eas submit` asks you to sign in to Apple and pick the app.

## 5. Build

To test on your own devices first, make an internal preview build:

```sh
eas device:create                          # once, to register your iPhone for ad hoc installs
eas build --profile preview --platform ios
eas build --profile preview --platform android
```

Open the link EAS prints on the phone to install the build. On Android, if the build is an `.aab` that the phone won't install, add `"android": { "buildType": "apk" }` to the `preview` profile in `eas.json` and build again.

Then make the store builds:

```sh
eas build --profile production --platform all
```

Build numbers increase automatically (`appVersionSource: remote`, `autoIncrement`).

## 6. Submit

**iOS to TestFlight:**

```sh
eas submit --profile production --platform ios --latest
```

The build shows up in TestFlight once Apple finishes processing it. Add yourself as an internal tester.

**Android to the Play internal track:**

1. In Play Console, create the app `Gradespace IDE` with package `com.gradespace.ide`.
2. Upload the **first** `.aab` by hand. Download it from the EAS build page, then go to Testing → Internal testing → Create release. Google only accepts API uploads after one manual upload.
3. Set up automated submits:
   1. Create a Google Cloud service account.
   2. Invite it in Play Console → Users and permissions with release permissions.
   3. Download its JSON key.
   4. Store the key outside the repo, then upload it with `eas credentials` → Android → production → Google Service Account. Alternatively, set `submit.production.android.serviceAccountKeyPath` in `eas.json` to the key's path.
4. Submit later builds with:

   ```sh
   eas submit --profile production --platform android --latest
   ```

   They go to the internal track, as set in `eas.json`.

## 7. Pair the phone with your Mac

1. Get the phone and the Mac talking to each other in one of these ways:
   - **Same Wi-Fi:** in the GS desktop app, open Settings → Connections and turn on network access.
   - **Anywhere:** install Tailscale on both devices and sign in to the same tailnet. The server is then reachable at its tailnet name.
2. On the Mac, create a pairing link in Settings → Connections. A QR code appears.
3. In the app, tap **Add environment** and scan the QR code with the in-app scanner. You can also paste the link or enter the host and code by hand.
4. On iOS, allow Local Network access when asked.

Use the in-app scanner, not the system Camera app:

- Some QR codes point at T3's hosted web app (`app.t3.codes/pair?host=…`). The in-app scanner reads the host from them and connects directly. The Camera app would open T3's website instead.
- `t3code://` links open T3 Code's app, not this one.

## 8. What needs T3's services

This build can't use T3's Clerk instance, T3's relay or T3's EAS project. When their settings are unset, the app hides those features and everything else still works:

| Feature                                                         | Without T3's services                                                                                                       |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Pairing over LAN or Tailscale, threads, terminals, diffs, files | Works. The app talks to your server directly.                                                                               |
| Sign-in and T3 Connect remote access                            | Hidden. Use Tailscale for remote access.                                                                                    |
| Push notifications and remote Live Activity updates             | Off. They're delivered by the relay over APNs/FCM after Clerk sign-in. You'll still see in-app state when you open the app. |
| Crash reporting                                                 | Off. It goes through the relay.                                                                                             |
| Over-the-air updates                                            | Work once `T3CODE_MOBILE_EAS_PROJECT_ID` is set, through your own EAS project (`eas update --channel production`).          |

To get push and remote access without Tailscale, you'd need to self-host the relay in `infra/relay` with your own Clerk instance plus APNs and FCM credentials, then set the variables from step 3. That's a project of its own and isn't needed to ship.
